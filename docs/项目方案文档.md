## 二、核心数据集（开源、高质量、丰富）

| 数据集 | 用途 | 体量 | 获取方式 |
|---|---|---|---|
| **NEU-DET** | 钢材表面 6 类缺陷(crazing/inclusion/patches/pitted_surface/rolled-in_scale/scratches)，1800 张，标注规范 | 主数据集 | 东北大学官网 |
| **Severstal (Kaggle)** | 钢材 4 类缺陷分割，12568 图 | 分割任务 | Kaggle |
| **MVTec AD** | 15 类工业异常检测基准 | 零样本/异常检测对照 | MVTec 官网 |
| **GC10-DET** | 金属表面 10 类缺陷 | 扩充验证 | GitHub |
| **Flowers/开放图像** | 仅做 Qwen-VL 零样本对照基线 | 旁路验证 | 公开数据 |

> 数据集丰富度与质量是本项目核心加分项——面试官常问"数据怎么来的、多大、怎么标注"。

## 三、技术选型（最优栈，不迁就旧记忆）

### 后端（Java 全栈主控）
- Spring Boot 3.5 + **Java 21**
- Spring Security + JWT 鉴权
- MyBatis-Plus、MySQL 8、Redis 7
- MinIO（缺陷图像对象存储）
- Milvus（缺陷特征向量库，做相似缺陷检索）
- Spring Scheduler（训练/推理任务异步队列）
- Micrometer + Prometheus + Grafana（监控）

### Python AI 服务（独立微服务，Java 通过 HTTP/gRPC 调用）
- Python 3.11 + PyTorch 2.x + **Ultralytics (YOLOv11)**
- HuggingFace Transformers（Qwen-VL）
- PEFT（LoRA 微调 Qwen-VL，可选）
- FastAPI（推理服务）
- ONNX / TensorRT（部署加速，可选）
- ClearML / MLflow（实验追踪）

### 前端
- Vue3 + Vite + TypeScript
- Ant Design Vue
- ECharts（缺陷分布/置信度看板）
- **Vue Flow**（质检流程编排）
- SSE 流式质检报告

### 工程化
- Docker Compose 一键启动
- GitHub Actions CI
- Colab / Kaggle 免费 GPU 训练 → 导出权重 → 本地推理

### 大模型推理
- 云端 API 为主：通义千问 / DeepSeek（生成质检报告）
- 本地 Ollama 兜底：跑 Embedding 和离线演示（符合低成本+灵活部署偏好）

## 五、分阶段实施

> 原则：每阶段产出**可独立运行 + 可验证**的成果，通过验收测试后再进入下一阶段，避免反复调试。

### 阶段 0｜环境与脚手架（地基）
**产出：** Docker Compose 起全栈、前后端骨架可登录可跑通
- `docker-compose.yml`：MySQL8 + Redis7 + MinIO + Milvus + Ollama(可选)
- Spring Boot 骨架 + Vue3 骨架 + FastAPI 骨架
- JWT 登录、健康检查、Swagger 文档
- **验收测试：** `curl /health` 全绿、前端登录页可登录、三服务互通

### 阶段 1｜数据集工程
**产出：** NEU-DET 入库 + EDA 看板 + 数据增强
- 数据集导入(NEU-DET/Severstal)、标注可视化、类别/尺寸/分布 EDA
- 数据增强 Albumentations(翻转/旋转/亮度/噪声)、按类均衡
- 数据集版本管理(目录版本 + 元数据)
- **验收测试：** 导入 1800 张 NEU-DET → EDA 6 类分布图 → 增强×5 → 9000 张入 MinIO；单元测试校验标注文件格式

### 阶段 2｜YOLO 训练 + 评估（核心 AI 能力）
**产出：** 训练管线 + 评估报告 + 权重导出
- Colab/Kaggle GPU 训练 YOLOv11n/s/m 三档超参
- 指标：mAP@0.5 / mAP@0.5:0.95、Precision/Recall、混淆矩阵、PR 曲线
- 过拟合/欠拟合诊断、学习率/数据增强调优
- 导出 best.pt + ONNX
- **验收测试：** mAP@0.5 ≥ 0.70（NEU-DET 6 类基线）、评估报告自动生成、ONNX 推理结果与 PT 一致性校验

### 阶段 3｜推理服务化 + 零样本对决（推理部署能力）
**产出：** Java→Python 推理链路 + Qwen-VL 零样本对比
- FastAPI YOLO 推理接口(图像→缺陷框+类别+置信度)
- Qwen-VL 零样本：prompt 直接问"有哪些缺陷"，对比 YOLO
- Java `inference-service` HTTP 调 Python、结果落库 + 推 Milvus
- 批量推理 + 异步队列(Spring Scheduler)
- **验收测试：** 上传一张图 → 后端→Python→返回框→前端绘制；YOLO vs Qwen-VL 在 100 张测试集的对比表(准确率/速度/成本)

### 阶段 4｜质检报告 + 溯源（LLM 应用能力）
**产出：** LLM 结构化报告 + 缺陷相似检索 + 趋势看板
- 用通义/DeepSeek 生成结构化质检报告(JSON Schema→PDF/Excel)
- Milvus 存缺陷裁剪图向量，"以图搜图"找历史相似缺陷
- 缺陷分布/批次/趋势 ECharts 大屏
- **验收测试：** 选一批次图像→生成报告含"缺陷类别统计/严重度/处置建议/相似历史案例"；JSON 输出符合 Schema 校验

### 阶段 5｜工程化收尾（求职加分项）
**产出：** 一键部署 + 监控 + 文档
- Docker Compose 完整编排(含 Python 服务)
- Prometheus 指标：推理 QPS / 延迟 / 模型置信度分布
- README + 架构图 + 演示视频脚本
- **验收测试：** 全新机器 `docker compose up` → 全栈可用；压测推理接口 P95 < 800ms
