## 分镜 0｜片头（0:00–0:30）

**画面**：项目标题卡——"SteelGuard AI 钢材表面缺陷智能质检平台"，副标题一行能力链：`数据工程 → YOLO 训练 → 双模型对决 → 批次质检 → 向量溯源 → LLM 报告 → 容器化监控`。

**解说词**：
> 大家好，这是我的全栈 AI 应用项目 SteelGuard，一个面向钢铁产线的表面缺陷智能质检平台。它基于东北大学 NEU-DET 数据集，覆盖从数据工程、模型训练到推理服务化和业务闭环的完整链路，并且全部跑在 Docker 容器里。

## 分镜 1｜一键部署（0:30–1:20）

**画面**：
1. 终端执行（可提前跑完，展示命令与结果）：`docker compose --profile gpu up -d`，随后 `docker compose ps`，十个容器全部 healthy/running。
2. 浏览器依次快速闪：前端 5173 登录页、AI 服务 `/health`（显示 device=cuda:0、RTX 4060）、Swagger doc.html、Grafana 3050。

**解说词**：
> 整条链路一键拉起：Nginx 前端、Spring Boot 业务网关、FastAPI 的 AI 服务，加上 MySQL、Redis、MinIO、Milvus、Prometheus 和 Grafana，共十个容器。AI 镜像我做了 GPU 和 CPU 两种模式，无显卡机器也能用 CPU 模式演示完整流程。健康检查可以看到，模型已经加载在我的 RTX 4060 上。

**画面备注**：切到 `/health` 时停留 2 秒，让观众看清 `torch 2.14 + cuda` 字样。

## 分镜 2｜数据集与 EDA（1:20–2:00）

**画面**：登录（admin/admin123）→ 数据集页面：版本卡片（v1-raw 1800 图 4189 框、v1-aug5 7200 增强图）、6 类分布、bbox 宽高/框数分布图。

**解说词**：
> 数据用的是 NEU-DET，1800 张灰度图、6 类缺陷各 300，共 4189 个标注框。我做了完整的数据工程：VOC 标注解析、探索性分析，以及按 bbox 同步的图像增强，增强集 7200 张全部带着正确标注。训练集和验证集 8 比 2 分层切分，增强副本不会跨集合，杜绝数据泄漏。

## 分镜 3｜现场上传 + YOLO/VLM 双模型对决（2:00–3:30）

**画面**：
1. 推理页上传一张划痕/夹杂图片（推荐 `scratches_1`、`inclusion_62`，框多对比明显）。
2. 左右双栏同时出结果：左侧 YOLO 秒出实线框 + 置信度；右侧 Qwen-VL 虚线框、耗时 8 秒级、token 与成本标签。
3. 再传一张裂纹 `crazing_*`，诚实展示 YOLO 置信度偏低。

**解说词**：
> 这是推理页，同一张图同时请求我的 YOLO 模型和通义千问 Qwen-VL 做零样本对照。YOLO 在 GPU 上十几毫秒出结果；VLM 平均要 8 秒，还有现金成本。我用 100 张验证集做过量化对决：YOLO 的 F1 是 0.677，VLM 零样本只有 0.034——这组数据回答了"工业质检为什么要用专用小模型"。
> 另外我不回避短板：裂纹类因为纹理细长、对比度低，mAP 只有 0.365，Roadmap 里我计划换 yolo11m 加类别过采样继续优化。

**技术插播（可选，屏幕角标文字即可）**：VLM 长 JSON 会半截断尾，我做了括号深度扫描等三重打捞，批处理失败率从 23% 降到 0。

## 分镜 4｜批次检测与 LLM 报告（3:30–5:00）

**画面**：
1. 批次列表 → 现场上传建批（选 6 张含 scratches/inclusion 的图）→ 列表 5 秒轮询进度到完成，展示缺陷数、严重度（critical/high 规则标签）。
2. 进入报告页：8 个事实卡片 → 点"生成报告"，按钮 loading 约 15 秒 → 报告渲染：严重度研判、分类别统计饼图、评价分析、处置建议（中文）。

**解说词**：
> 实际产线是成批检测的。创建批次后，Java 网关异步调度：逐张调 YOLO、结果落 MySQL、有缺陷的框自动进向量库。跑完后可以一键生成 LLM 质检报告。
> 这里我重点解决幻觉问题：报告里所有数字——缺陷数、占比、严重度——全部由 Java 聚合后注入 prompt，LLM 只能引用不能造数；输出走 JSON Schema 强校验，不合格带错误信息修复重试一次；最终严重度以程序规则为准并留痕，脏报告绝不入库。一份报告约 1700 token，成本人民币两厘。

## 分镜 5｜相似缺陷溯源（5:00–5:50）

**画面**：报告页下滑到"相似历史案例"图片墙（裁剪图、类别、置信度、来源批次）；或在推理页对某个检测框点"溯源"，展示返回的历史相似框。

**解说词**：
> 每个检测框我都会裁剪后用 ResNet50 提取 2048 维特征存进 Milvus。历史库有 4839 个案例，先检测再按框溯源的 top1 同类率是 93.3%——比直接拿整图搜的 63% 高很多，因为细长缺陷会被背景淹没。检索还支持按类别过滤、排除本批次自身，报告里引用的相似案例就是这么来的。

## 分镜 6｜趋势看板与导出（5:50–6:40）

**画面**：缺陷趋势页：6 个 KPI、7/30/90 天切换、类别环图、双轴柱图；回到报告页点"导出 Excel"（展示 4 个 Sheet）→"导出 PDF"（A4 多页，图片正常入图）。

**解说词**：
> 趋势看板汇总批次量、缺陷率和类别分布，给质量管理人员看宏观趋势。报告支持一键导出 Excel 和 PDF，PDF 是前端 html2canvas 加分页 jsPDF 生成的，证据图片直接嵌在报告里，可以直接进质检台账。

## 分镜 7｜监控与压测（6:40–7:40）

**画面**：
1. Grafana 看板（时间范围选压测时段，如最近 30 分钟/1 小时）：AI QPS、P50/P95/P99 曲线（指出 800ms 验收线）、6 类检出速率、Java 网关 P95、JVM/Tomcat 面板。
2. 切到 `ai-service/reports/loadtest_gpu_*.md`（或 PPT 数字卡）：10/20/50 三档表格。

**解说词**：
> 上线不能只看功能。Python 和 Java 两端我都埋了 Prometheus 指标，Grafana 12 个面板开箱即用。我做了 10、20、50 三档阶梯压测，每档 500 个真实图片请求走完整链路：20 并发下 P95 是 446 毫秒、零错误，优于 800 毫秒的验收线；50 并发 QPS 封顶在 55，我定位到瓶颈是 YOLO 推理的全局串行锁，扩容方向是 batch 合并、多 GPU 副本或 TensorRT。

## 分镜 8｜技术总结（7:40–8:40）

**画面**：README 架构图（Mermaid 大图）→ VS Code 快切 4 个关键文件（各停 3 秒）：
`app/report/builder.py`（防幻觉）、`app/trace/embedder.py`（Embedding）、`InspectionService.java`（异步编排）、`app/metrics.py`（埋点）；最后终端跑 `pytest -q` 显示 121 passed。

**解说词**：
> 技术栈上，后端是 Java 17 加 Spring Boot 3.5，JWT 鉴权、异步编排；AI 服务是 FastAPI 加 PyTorch；前端 Vue3 加 ECharts；向量库 Milvus，对象存储 MinIO，整套用 Docker Compose 编排，Python 侧有 121 个测试覆盖真实踩过的坑。这个项目把"模型能用"和"系统能上线"之间的工程问题都走了一遍。
